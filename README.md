# Sudhanshu Ranjan - Car Price Prediction

## 1. Project Overview

This project analyzes the 2021 car specification dataset and predicts a car's ex-showroom price. It was created by **Sudhanshu Ranjan**.

The project includes:

- Data loading and cleaning
- Missing-value handling
- Text-to-number conversion for values such as `1998 cc`, `1350 kg`, and `24 litres`
- Categorical feature encoding
- Random Forest price prediction
- Model evaluation
- Flask backend API
- Streamlit dashboard frontend
- Word report generation
- Project verification

The target column is `Ex-Showroom_Price`.

## Dataset Source

The dataset used in this project is the **Indian Cars Dataset** from Kaggle:

[Indian Cars Dataset on Kaggle](https://www.kaggle.com/datasets/medhekarabhinav5/indian-cars-dataset?select=cars_ds_final_2021.csv)

The project uses the file `cars_ds_final_2021.csv` from that dataset.

## 4. Dataset

The input file is `cars_ds_final_2021.csv`. It contains car details such as:

- Make, model, and variant
- Ex-showroom price
- Engine displacement and cylinders
- Fuel type and fuel tank capacity
- Height, length, width, and kerb weight
- Body type, doors, gears, and seating capacity
- Mileage, ground clearance, power, and torque
- Brake type and safety/equipment specifications

The dataset contains 1,267 rows. The target is the ex-showroom price stored as text containing currency symbols and commas, for example `Rs. 2,92,667`.

## 5. Complete Data-Analysis Process

### Step 1: Load the dataset

The pipeline reads the CSV from the same folder as the Python file. This makes the project portable across computers:

```python
pd.read_csv("cars_ds_final_2021.csv")
```

### Step 2: Select useful columns

The project keeps the specifications that are useful for price prediction, including vehicle identity, dimensions, engine details, fuel information, safety features, and equipment.

### Step 3: Clean the target price

The `Ex-Showroom_Price` column is converted from text to numeric values by removing `Rs.`, commas, and other non-numeric characters. Rows without a usable target price are removed.

### Step 4: Convert specification text to numbers

Values with units are converted to numeric values. Examples include:

- `624 cc` becomes `624`
- `24 litres` becomes `24`
- `725 kg` becomes `725`
- `180 mm` becomes `180`
- `38PS@5500rpm` becomes `38`

The same numeric extraction approach is used for doors, gears, cylinders, dimensions, power, torque, and other numeric specifications.

### Step 5: Handle missing values

- Numeric columns use median imputation.
- Categorical columns use most-frequent-value imputation.
- The pipeline preserves rows instead of deleting cars simply because one specification is missing.

### Step 6: Encode categorical values

Text columns such as make, model, fuel type, body type, brake type, and transmission type are converted using one-hot encoding. Unknown categories received later by the API are safely ignored by the encoder.

### Step 7: Split the dataset

The cleaned data is divided into:

- 80% training data
- 20% testing data

The split uses `random_state=42` so results are reproducible.

### Step 8: Train the model

The project trains a `RandomForestRegressor` with:

- 250 trees
- Maximum depth of 18
- Fixed random state of 42
- All available CPU cores for training

The preprocessing and model are stored together in one scikit-learn pipeline.

### Step 9: Evaluate the model

The model is evaluated using:

- **MAE:** average absolute prediction error
- **RMSE:** gives more weight to large errors
- **R2:** proportion of price variation explained by the model

The original exploratory notebook achieved the following results on its fixed test split:

| Model | MAE | RMSE | MAPE | R2 |
|---|---:|---:|---:|---:|
| Random Forest | 149,663.32 | 320,467.42 | 8.49% | **0.978769** |
| Linear Regression baseline | 238,985.06 | 388,509.88 | 12.39% | **0.968796** |

Rounded for presentation, these are **0.97 for Random Forest** and **0.96 for Linear Regression**. Random Forest performed better because it can model non-linear relationships between vehicle specifications and price.

The standalone API training pipeline uses a slightly different reusable preprocessing configuration, so its metric can differ from the notebook benchmark. The notebook comparison above is the official project-analysis result.

### Step 10: Save the model

The trained pipeline is saved as `car_price_model.joblib`. The Flask API and Streamlit application load this file to make predictions without retraining every time.

### Step 11: Generate the report

`generate_report.py` creates:

- `SudhanshuRanjan_ProjectReport.docx`
- `model_performance.png`

The Word report contains the project title, dataset preparation process, model metrics, actual-versus-predicted chart, interpretation, limitations, and usage instructions.

## 9. Backend API

The backend is implemented in `app.py` using Flask.

Start the backend:

```powershell
.\.venv\Scripts\python.exe app.py
```

The API runs at:

```text
http://127.0.0.1:5000
```

### Health check

Open this URL in a browser:

```text
http://127.0.0.1:5000/health
```

Expected response:

```json
{
	"status": "ok",
	"model_ready": true
}
```

### Prediction request

Send a `POST` request to `/predict` with JSON. Example using PowerShell:

```powershell
$body = @{
		Make = "Tata"
		Model = "Nexon"
		Variant = "XZ"
		Displacement = "1199 cc"
		Cylinders = 3
		Fuel_Type = "Petrol"
		Body_Type = "SUV"
		Power = "118PS@5500rpm"
		Torque = "170Nm@1750rpm"
		Seating_Capacity = 5
} | ConvertTo-Json

Invoke-RestMethod -Uri "http://127.0.0.1:5000/predict" -Method Post -Body $body -ContentType "application/json"
```

The response contains a predicted price:

```json
{
	"predicted_price": 850000.0
}
```

Missing fields are handled by the pipeline's imputers. The API returns an error message if the request is not valid JSON or the model cannot make a prediction.

## 10. Streamlit Dashboard

Start the interactive frontend:

```powershell
streamlit run streamlit_app.py
```

The dashboard contains three views:

- **Overview:** total cars, brand count, median price, model R2, price distribution, brand listings, and error metrics.
- **Market Explorer:** filter by brand, body type, and fuel type; compare prices by body type; inspect displacement versus price; and view the highest-priced matching listings.
- **Predictor:** enter vehicle identity and specifications, then receive an estimated ex-showroom price.

On the first run, the application trains the model automatically if `car_price_model.joblib` does not exist. Data and the model are cached so the dashboard remains responsive while switching views.

## 13. Limitations and Future Improvements

- The model uses one train/test split rather than cross-validation.
- The dataset contains many vehicle categories, so one-hot encoding can create many features.
- Luxury and rare vehicles may have larger absolute errors.
- Gradient boosting or XGBoost could be compared with Random Forest.
- A logarithmic transformation of price could improve performance across a wide price range.
- Hyperparameter tuning could improve the model.
- More recent market data would improve real-world price relevance.
